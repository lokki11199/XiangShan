# Спецификация документа v5 (для исполнителя)

Архитектор: основная сессия. Исполнитель пишет генератор и собирает PDF. Документ — главный результат работы
для пользователя, поэтому точность важнее объёма.

## Что сделать

1. Генератор `core-reset/doc/make_pdf.py` (Python 3 + reportlab 5, шрифты DejaVu Sans / Sans Mono из
   `/usr/share/fonts/truetype/dejavu/`; matplotlib нет — графику рисовать `reportlab.graphics`).
   Выход: `core-reset/xscore_reset_v5.pdf`. Запуск: `python3 core-reset/doc/make_pdf.py` из корня репозитория.
   В ветке скрипты должны остаться (в v4 они потерялись).
2. Документ **управляется данными**: все числа берутся из файлов результатов, а не вписываются руками:
   - `core-reset/verification/results_formal_k.txt`, `results_formal_s.txt` (prove 100/16 с временем, bmc,
     covers со ступенями, мутанты: свойство и такт контрпримера, эквивалентные мутанты);
   - `results_equiv.txt` (5 миттеров);
   - `regress_summary.txt`, `results_regress.txt`; `results_soak_KEEP.log`, `results_soak_CFG_SWEEP.log`;
     `coverage_KEEP.json`, `coverage_CFG_SWEEP.json`;
   - результат полной elaboration XSNoCTop — файл `core-reset/verification/results_elab.txt` (его напишет
     архитектор; если файла нет — писать «не выполнена»);
   - фрагменты патча — из `git diff 7b16188 HEAD -- src/` (по файлам, подсветка: зелёный — добавлено,
     красный — удалено, серый — контекст).
   Если файла результатов ещё нет, генератор пишет в документ явное «нет данных», а не падает.
3. Временные диаграммы (раздел 7.4) — из VCD: сборка тестбенча с трассировкой
   (`TRACE_BUILD=1 scripts/run.sh <scen> <seed> <cfg> +VCD +VCD_FROM=.. +VCD_TO=.. +VCD_FILE=..`), свой
   разбор VCD на Python (`core-reset/doc/vcd.py`), отрисовка reportlab. Скрипт получения VCD —
   `core-reset/doc/make_waves.sh` (окна по тактам находить автоматически по событиям в логе/VCD, а не числами).
4. Текст — по-русски, подробно, в стиле v4. Основа текста — v4: `pdftotext -layout` лежит в
   `/tmp/claude-0/-home-user-XiangShan/2bcef260-de74-50c9-af63-846e811d3893/scratchpad/v4pdf/v4.txt`
   (5110 строк; оглавление: `grep -nE "^ {0,4}[0-9]+(\.[0-9]+)*\. " v4.txt`). Неизменившиеся части
   (понятия TileLink и Debug Module, справочник модулей, обход L1D, AcquirePerm, как CoupledL2 принимает
   Release и ProbeAck, изоляция домена сброса) переносить, сверяя с кодом v5 и убирая всё про импульс / sHold /
   CoreResetLevel / 16 тактов.

## Стиль (как v4, см. первые страницы PDF v4)

- A4, поля ~2 см; заголовок документа крупный жирный, под ним серый подзаголовок; на первой странице —
  сводная таблица «Что / Где»; колонтитул снизу: короткое имя документа слева, номер страницы справа.
- Таблицы: шапка с серой заливкой, тонкие линии; идентификаторы кода — моноширинный тёмно-красный.
- Ссылки на спецификацию TileLink: 1.8.1 — `[TL 1.8.1 x.y, с. N]` **синим**, 1.9.3 — `[TL 1.9.3 x.y, с. N]`
  **зелёным** (номера разделов и страниц брать из v4.txt, где они уже есть; новых не выдумывать). Используемые:
  приоритет каналов A < B < C < D < E [1.8.1 2.2, с. 12]; снятие valid непринятого beat-а [1.8.1 4.1, с. 19];
  правило прогресса [1.8.1 5, с. 28]; 100 тактов сброса [1.8.1 3.2.2]; адаптер для раздельного сброса
  [1.8.1 3.2.3]; ProbeAck NtoN законен.
- Врезки «Почему так» (светлая заливка, рамка) с обоснованием решений.
- Блок-схемы и диаграммы последовательностей рисовать (reportlab.graphics): структура тайла с гейтами, автомат
  CoreResetCtrl (5 состояний), DCacheFlushUnit, последовательности KEEP и SWEEP, диаграмма изоляции
  «sReset (≥ 100 тактов и до снятия запроса)».

## Факты v5 (сверять с кодом)

- `CoreResetCtrl(keepL1, rstCycles = 100)`: `sIdle → sFlush` по запросу; `sFlush → sDrain` при
  `l1Done && earlyQuiet`; `sDrain → sReset` при `gatesQuiet && l1Done && l1Idle` (тот же такт;
  `coreReset`, `hartInReset`, `closed` := 1); `sReset → sRelease` при `cnt >= rstCycles && !req`;
  `sRelease → sIdle` при `l1.alive && !coreInReset`. Выходы: `l1.req` = sFlush|sDrain, `l1.freeze` = KEEP &&
  closed, `earlyBlock` = state ≠ sIdle, `gateBlock` = sDrain | closed, `holdProbe` = KEEP ? sDrain|closed :
  sDrain, `ackProbe` = SWEEP && closed, `isolate` = closed. Assert-ы: gatesQuiet в sReset, closed ≡
  sReset|sRelease, coreReset ⇒ closed.
- Гейты: l1d (TL-C, `early = false`), l1i, ptw, i_mmio, d_mmio (TL-UL, `early = true`); `QuiesceGateIO`
  без `idle`; `TLResetIsolation.quiet`.
- `DCacheFlushUnit`: sIdle → sDrain → (sSweep → sWait) → sDone по `idle` = все четыре флага;
  `L1QuiesceIO.idle`.
- Порты тайла и XSNoCTop не изменились.

   l1.done/idle, строк в L1D / в директории, события C/D/B, gateBlock, holdProbe, ackProbe, isolate, сброс ядра,
   сброс frontend, alive).

   последнем такте sFlush, sDrain ждёт его ProbeAckData через буфер C, затем сброс.
3. KEEP, SCEN 6 seed 1, случай 4 (Probe toN грязной строки в первом такте sDrain): Probe держится весь сброс,
   после запуска — ProbeAckData из «горячей» L1D. Ожидание рисовать уровнем (B предложен и не принят), выход
   буфера B во время сброса маскировать (там мусор).
4. Момент установки сброса крупно: holdProbe с первого такта sDrain, L2 предлагает Probe, B ready = 0;
   coreReset и isolate на одном фронте; случайные выходы ядра в сбросе замаскированы на стороне тайла.
